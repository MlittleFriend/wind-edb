# 如何调取特定日期下的特定数据

## 1. 先把问题翻译成可核对的取数条件

记录：指标含义、地区/人群/行业、单位、频率、统计口径、目标统计期、是否要求“当时可知”。例如“2025 年上半年全国居民收入”对应全国居民人均可支配收入、元、季度、累计值、2025-06-30；不能用城镇居民收入、同比、单季值替代。

| 用户请求 | 应怎样理解 |
|---|---|
| 2025 年 6 月 CPI 同比 | 月度、同比、2025 年 6 月的统计期；不是 6 月发布日期 |
| 2025 年二季度收入 | 单季还是上半年累计？若上下文不足需澄清；不能默认二者相同 |
| 2025 年上半年居民收入 | 季度累计指标的 2025-06-30 观测 |
| 2025 年全年收入 | 年度值或季度累计指标 2025-12-31；先核对口径 |
| 最近 12 期 | 12 个观测，不是 12 天；最新期可能滞后当前日期 |
| 截至 2025-06-30 当时已知的数据 | 需要发布日期和历史版本（vintage）证据；普通 EDB 日期筛选不足以实现 |

EDB 当前返回的历史序列可能包含后续修订。把 end 设为过去某日，只约束统计观测日期，不会自动回到那天的信息集。没有历史版本/发布档案时，应明确“当前版本的历史数据，未验证历史时点可得性”。

## 2. 找到正确指标，而不是猜代码

先查已有健康底稿：`edb_tools.py inspect ... --configs-dir configs`。在导出的 JSON 中搜索 metric 的 name、code、unit、freq、funcName 与 changeRecord，比较候选的地区、累计/当期/同比、名义/实际、季调与否等。已有指标仍需按本次任务口径复核。

若模板中不存在所需指标，通过当前 Wind 指标浏览器搜索关键词、查看指标解释及来源，再导出一个带连接的 Excel 小样并解码。不能仅将其他指标的 code 改成猜到的代码，却保留旧名称、频率和单位。也不能把其他供应商的 EDB 代码当成 Wind 代码。`prepare_query.py` 不具备全库搜索能力；它只选择模板中已经存在的完整 metric。

已在 Excel 中核验过返回标题的两个例子（代码仍应在目标环境检查）：

| Wind 代码 | 名称 | 单位 | 频率/口径 |
|---|---|---|---|
| M5481759 | 中国:居民人均可支配收入:累计值 | 元 | 季度累计 |
| M5481772 | 中国:居民人均消费支出:累计值 | 元 | 季度累计 |

因此要“2025 年二季度单季收入”，不能直接把 M5481759 的 6 月值当作答案。若适合该指标的统计定义，可用上半年累计减一季度累计另建派生列，清楚标注推算，并先核对修订、人口分母与可加性；优先选择原生单季指标。同比、比率、指数、均价不能普遍用累计相减。

## 3. 将日期写进批注配置

已实测的模式如下；公式仍是 `='WindFunc.xla'!edb()`，不是把日期硬塞进这个无参数公式。

| 目标 | periodType | 生效字段 |
|---|---|---|
| 指定单个统计日期 | ptObsBetween | obsFrom 与 obsTo 相同 |
| 指定日期区间（含边界） | ptObsBetween | obsFrom、obsTo |
| 最近 N 个观测 | ptLastObs | lastType=ltObservations、lastObs=N |
| 全部历史 | ptFullPeriod | 不要假定旧的 obsFrom/obsTo 会限制返回 |

单期示例（将以下字段合并到完整已核验配置，不能只用这个片段替代整个批注）：

```json
{
  "timeFrameSetting": {
    "periodType": "ptObsBetween",
    "obsFrom": "20250630",
    "obsTo": "20250630"
  }
}
```

脚本保留其余字段与指标转换，避免抹掉模板设置。若模板带同比、季调等转换，而任务需要原始值，先在插件中取得正确的原始模板，不能盲目清空转换字段。

```powershell
# 同一统计日的一条指标
python scripts/prepare_query.py --template configs/connection-2.json --codes M5481759 --start 2025-06-30 --end 2025-06-30 --output query-single.json

# 指定年度内两条季度指标
python scripts/prepare_query.py --template configs/connection-2.json --codes M5481759 M5481772 --start 2025-01-01 --end 2025-12-31 --output query-range.json

# 一条指标的最近两个观测
python scripts/prepare_query.py --template configs/connection-2.json --codes M5481759 --last 2 --output query-last.json

# 选择上面的配置进行原生刷新
python scripts/probe_excel.py --config query-single.json --output probe-single.xlsx --addin '<Wind安装目录>/WindFunc.xla'
```

`connection-2.json` 是演示文件名，不是固定数据库；先确认它的 metric 包含所需代码。命令输出路径必须尚不存在。

日期规则：

- 使用真实的日历日期。月度通常以月末、季度通常以季末标记，但必须查看该指标实际返回日期，不能仅凭标签猜测。
- 不知道月度观测落在哪天时，先请求该月月初到月末，再检查返回日期，不做近似匹配。
- 日度数据遇周末/节假日不一定有观测；单日缺值不是函数故障。不自动前值填充。若用户明确要求“截至该日最近观测”，取一个覆盖此前日期的区间，在返回日期中选最大且不晚于截止日者，展示实际观测日及滞后天数；这仍不是当时发布版本的证明。
- 混合频率指标分开取数最容易核验。确需合表时按日期显式对齐，空白不得当零，也不擅自前向填充。
- `--last` 是随刷新移动的窗口；用于固定历史底稿时应使用明确起止日期。

## 4. 验证筛选，再把值接到报告单元格

实测中，筛选 2025-06-30 后，标题“时间区间”仍显示整条序列的历史范围。因此必须核对**实际日期列**、指标 ID 列头、返回行数和数值；不能仅看标题或 UsedRange 推断筛选成功。历史范围与更新时间也不是逐期发布日期。

本次季度累计示例的返回标题占 A4:B12，真实数据从 A13 开始；这不是固定布局。标题选项、转置、指标数量会改变位置，其他底稿必须重新识别。

报告单元格优先按日期精确查找，避免硬引用“第 20 行”或取末行。以下假设：已核验 EDB_raw 的 A13:A1000 是纯 Excel 日期、B 列是唯一目标指标，E2 是目标日期。范围上限需按实际序列维护，不能截断：

```excel
E2 = DATE(2025,6,30)
F2 = MATCH(E2,'EDB_raw'!$A$13:$A$1000,0)
G2 = IF(COUNTIF('EDB_raw'!$A$13:$A$1000,E2)<>1,NA(),IF(ISBLANK(INDEX('EDB_raw'!$B$13:$B$1000,F2)),NA(),INDEX('EDB_raw'!$B$13:$B$1000,F2)))
```

这里 E2/F2/G2 是单元格位置说明；输入单元格的内容从等号开始。明确使用 MATCH 的 0 精确匹配；缺失、重复日期和空白会暴露为错误，不能 `IFERROR(...,0)` 掩盖。若返回空字符串还需单独检查字符串空值；若日期是文本，先在辅助列按明确格式规范化，再查找，不能用易受地区设置影响的隐式转换。实际返回的错误或 N/A 不替换成零。

日期在多列指标中精确匹配之前，还需通过指标代码确认列位置；列顺序可能随配置变化。不要在列名相似时仅按列号选取。

## 5. 验收记录

记录请求代码/名称/单位/口径、日期类型、有效日期模式、起止日期、实际返回日期列表/首末日期、行数、缺失情况、取数时间、保存后配置与公式核对。原始 EDB 页保留可刷新连接；报告引用与派生计算另放单元格。

对单期、全年区间和最近 2 期做过原生 Excel 小样，保存后读取实际日期/值，并与同一已返回全历史序列的对应数据比较。测试证明当前插件下这些参数按上述方式工作；不构成跨版本保证，也不是官方历史数值复核。
