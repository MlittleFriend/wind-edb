# 指标池：先找代码，再谈连接

EDB 连接的技术格式（公式 + 批注）只是载体，真正决定能不能取到数的是 `metric.code`。
实测：**代码不在 Wind 安装目录里，在用户自己的历史底稿里**。

## 1. 别在 Wind 安装目录里找代码（负结果，别再试）

| 位置 | 实际情况 |
|---|---|
| `etc/edb/EDBNew*.chs` | 二进制分词索引，只有碎片化指标名词，没有 code↔name 明文配对 |
| `etc/wdf/Indicator.xml` | 加密，不可读 |
| `etc/Matrix/wind_IndicatorTree.dat` | 压缩，GBK 明文搜不到 |
| `res/wings/etc/HQ/Base/formulaBasicIndicator.json` | 22MB 明文 JSON，但只含财务/基本面指标，无宏观 EDB |
| `DataBrowse/XLA/WindFunc.xla` | 7.4MB 加载项代码，指标数据在服务端，文件里没有代码表 |

这些路径加起来花了很久且全部失败。直接跳到第 2 步。

## 2. 建指标池（最高杠杆的一步）

```powershell
python scripts/pool_metrics.py --roots "<指标库目录A>" "<指标库目录B>" --out pool.json
python scripts/pool_metrics.py --roots "<指标库目录>" --terms 福建 人口 --out pool.json
```

按文件体积降序解码（大底稿更可能有 Wind 连接），默认取前 20 个。输出每个 code 的
`name / unit / freq / changeRecord` 和它在哪本底稿的哪个锚点，可直接作为新连接的模板。

配套的 `workbook_query.py search 底稿.xlsx --terms 关键词` 用于单本底稿精查；池化脚本用于
"不知道在哪本底稿"时的广撒网。两者都只做字面匹配，选中候选后必须人工核对口径。

## 4. 邻近代码探测 + 数值验证

不要凭形式"推断"代码，但可以在无浏览器可用时做**候选探测**，前提是用独立已知值验证：

1. 同族指标常连续编号。`M0001428` 是社零当月同比，则当月值很可能在同一区间。
2. 把 6–8 个候选放进**同一个锚点**，`freq` 取已知值，`name` 用 `cand:<code>` 占位，
   `timeFrameSetting` 设为 `ptObsBetween`，`obsFrom = obsTo` 指向一个你已知基准值的月份。
3. 一次 Excel 重算（20–30 秒）就能同时看全部候选。落在预期量级的那条即为命中。
4. **致命陷阱**：返回表的"指标名称"行回显的是你传进去的 `name`，**不是服务端真实名称**。
   因此名称完全不能用来判断代码对不对，只有数值量级和口径能判断。
5. 命中后立刻在 Wind 指标浏览器确认名称/单位/口径，再改回真实元数据。未确认前，
   在交付物里标注"代码由数值比对推定，名称待确认"。

探测示例：`M0001427` 在 2024-12 返回 45,171.50 亿元，与全国社零当月值量级一致，而
`M0001429`、`M0001430` 返回 0——说明探测要成组做，单点试错成本高。

## 5. 返回表布局（用 UsedRange 判断，不要假定）

以 `A4` 为锚点、多指标横排的实测布局：

```
A4  Wind                       ← 表头，这是正常返回，不是错误码
A5  指标名称   B5 指标1   C5 指标2 ...
A6  2025-12   B6 值1      C6 值2
A7  2025-11   ...
```

- 指标**横排**（每个指标一列），日期只出现在 A 列一次，期间数决定向下溢出的行数。
- 单期查询（`obsFrom = obsTo`）只返回 1 行数据。
- 标题/转置/指标数量都会改变布局。`references/specific-data.md` 里"标题占 A4:B12、数据从
  A13 开始"是另一种配置下的结果，**不要跨底稿套用行号**。
- 取报告单元格用 `MATCH` 按日期精确查找，不要写死第几行。

## 6. 用官方发布数交叉校验

同一指标同时有 Wind 和官方口径时，做一次一致性核对，这是给数据背书最省力的动作：

| 指标 | Wind（2025-12 累计） | 官方决算 | 差 |
|---|---|---|---|
| 国内消费税 | 16,857.00 | 16,857.47 | 取整 |
| 城市维护建设税 | 5,170.00 | 5,170.04 | 取整 |
| 公共财政收入 | 216,045.00 | 216,049.86 | 取整 |

差异应在取整误差（<1 亿元）内。若差异明显，先查四处口径：是否含进口环节、本级还是全国、
累计还是当月、是否含出口退税冲减。**Wind 与官方不一致时以官方决算为准，并在底稿里注明两者差异。**

## 7. 没有 pywin32 时怎么写入

`probe_excel.py` 依赖 pywin32。本机没有 pywin32 时它直接不可用，但协议可以 1:1 复现：

```powershell
pwsh -File scripts/edb_write.ps1 -CommentFile cmt.txt -Anchor A4
pwsh -File scripts/edb_write.ps1 -CommentFile cmt.txt -Anchor A4 -Workbook 底稿.xlsx -Sheet 'EDB_raw' -Save
```

`cmt.txt` 是 `edb_tools.pack_config(config)` 的输出。脚本流程与 `probe_excel.py` 完全一致：
打开 XLA → 写批注 → 写公式 → 计算 → 轮询 → 读实际 UsedRange。

补充两点：

- `$excel.Calculation = -4105` 在部分环境会抛 `HRESULT: 0x800A03EC`，但重算依然发生，
  不要因为这个异常中断流程。
- 打开 XLA 是必需的。不打开时公式会返回占位文本 `Wind`（看起来像成功，其实是表头），
  这是最容易误判为"函数坏了"的地方。

## 8. 写回已有底稿后的验收

用 Excel COM 改单元格后保存，连接可以保留；用 openpyxl 重存会丢批注和外链。保存后立刻复查：

```powershell
python scripts/edb_tools.py inspect 底稿.xlsx --out after.json
```

确认 `anchors` 里目标锚点仍在、`config` 可解码、`external_links` 数量未减少、`errors` 为空。
实测：COM 修改无关单元格并 `Save()` 后，原 `[1]!edb()` 锚点、批注配置、2 条外链全部完好。

> 本文件记录的是在 Windows + Excel + Wind 26.6.1 插件环境下的实测结果，不构成跨版本保证；换机器须重新探针核验。
